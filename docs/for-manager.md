# СтройCRM: коротко для руководителя

**Что это.** Небольшая внутренняя система для строительной компании: список объектов (стройплощадок) и задач по ним. Вместо переписки в мессенджерах — одна карточка задачи, в которой всегда видно, кто за неё отвечает, на каком она этапе и что происходило раньше.

**Кто в системе.** Две роли:

- **Постановщик** — ставит задачи: создаёт объекты и задачи, назначает исполнителей, проверяет результат.
- **Исполнитель** — выполняет задачи: видит только порученное ему и двигает задачу по этапам.

**Как задача проходит путь.** Новая → В работе → На проверке → Принята. Если работа сделана не полностью, постановщик возвращает задачу на доработку и обязательно пишет, что именно исправить. Исполнитель видит этот комментарий прямо в карточке, исправляет и снова отправляет на проверку. Каждый шаг доступен только тому, кому он положен: взять в работу может лишь назначенный исполнитель, а принять или вернуть — только постановщик. Перескочить этап нельзя, и уже принятую задачу нельзя «откатить» назад.

**Как защищены данные.** Главный принцип: правила записаны не в кнопках интерфейса, а в самой базе данных. Поэтому их нельзя обойти, даже если зайти в систему не через сайт, а напрямую в хранилище, — база просто откажет.

1. **Каждый видит только своё.** Исполнитель видит свои задачи и только те объекты, по которым у него есть работа. Чужие задачи и объекты ему недоступны — и на экране, и на уровне хранилища.
2. **Историю нельзя переписать.** Каждый переход статуса записывается в журнал: кто, когда, из какого статуса в какой и с каким комментарием. Записи журнала нельзя ни изменить, ни удалить — можно только добавить новую.
3. **Роль нельзя присвоить себе.** Никто не может «повысить» себя до постановщика: роли назначает только администратор проекта, а самостоятельной регистрации в системе нет.
4. **Без входа не видно ничего.** Анонимный посетитель не увидит даже названий объектов.
5. **Удаление ограничено.** Объект, в котором есть задачи, удалить нельзя — чтобы случайно не стереть работу. Задачу можно удалить, только пока она не начата.

**Что не может сделать исполнитель:**

- видеть задачи и объекты, которые ему не назначены;
- создавать объекты и задачи;
- менять название, описание, объект или исполнителя задачи после начала работы;
- произвольно менять статус — ему доступны только «Взять в работу» и «Отправить на проверку»;
- принять задачу самому себе или удалить её;
- изменить журнал статусов или выдать себе другую роль.

**Что пока за рамками.** Нет уведомлений по почте, сроков (дедлайнов), вложений и обсуждений внутри задачи. Это следующий шаг развития; на основную работу «поставил — выполнил — принял» всё перечисленное не влияет.
